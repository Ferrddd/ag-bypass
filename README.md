# Antigravity Linux Bypass (ag-custom)

Легковесное, полностью автономное решение для работы с **Google Antigravity** в заблокированных регионах без сторонних прокси-демонов, внешних зависимостей и привязок к HWID.

---

## ⚡ Особенности

- **0 внешних зависимостей:** Работает «из коробки» на стандартной библиотеке Python 3 (`socket`, `ssl`, `struct`, `pathlib` и т.д.). Никаких `pip install`, `virtualenv` или компиляторов.
- **Без локальных демонов:** Не держит в памяти постоянно работающие proxy-серверы. Система обращается к узлам обхода напрямую через быстрое SNI-проксирование.
- **Точечная маршрутизация (Split-DNS):** Через `/etc/hosts` перенаправляются исключительно рабочие и авторизационные домены Antigravity (`daily-cloudcode-pa.googleapis.com`, `cloudcode-pa.googleapis.com`, `oauth2.googleapis.com`, `accounts.google.com` и др.). Весь остальной интернет-трафик системы идёт напрямую.
- **Автоматический выбор лучшего узла:** Резолвит актуальные IP через SmartDNS или проверяет заданные узлы, тестирует TLS 443 хэндшейк и ранжирует узлы по минимальному пингу.
- **Авто-патчинг клиента:** Находит бинарник `agy` и безопасно модифицирует проверку доступности региона (`ineligible` $\to$ `inexigible`, 10 байт в 10 байт) с сохранением `.bak` бэкапа.
- **Фоновый мониторинг (Systemd Timer):** Системный таймер проверяет доступность узла каждые 2 минуты (настраивается в `config.json`) и при падении автоматически бесшовно переключается на живой резервный сервер без перезапуска клиента.

## 🚀 Быстрый старт

### 1. Установка
```bash
git clone <repo-url> ag-custom
cd ag-custom

# Базовая установка (создаёт команду ag в ~/.local/bin/ag):
./install.sh

# Или системная установка с таймером авто-восстановления:
sudo ./install.sh
```

### 2. Включение обхода
```bash
sudo ag on
```
Команда:
1. Автоматически найдёт и пропатчит клиент `agy` (создав резервную копию `agy.bak`).
2. Запросит актуальные IP у SmartDNS.
3. Проверит скорость каждого узла через TLS-рукопожатие на порту 443.
4. Добавит лучший узел в `/etc/hosts` и сбросит системный DNS-кэш (`resolvectl flush-caches`).

### 3. Проверка статуса
```bash
ag status
```
Выведет:
- Статус патча бинарника `agy`
- Текущие записи в `/etc/hosts`
- Проверку доступности активного прокси-узла и его задержку в миллисекундах
- Состояние службы фонового мониторинга

### 4. Отключение обхода
```bash
sudo ag off
```
Бесследно удаляет блок записей из `/etc/hosts` и сбрасывает кэш DNS.

## ⚙️ Конфигурация (`config.json`)

Вся настройка осуществляется через простой JSON-файл:

```json
{
  "smart_dns": {
    "servers": [
      "dns1.example.com",
      "1.2.3.4"
    ],
    "port": 53,
    "timeout_seconds": 3.0
  },
  "nodes": [],
  "domains": [
    "daily-cloudcode-pa.googleapis.com",
    "cloudcode-pa.googleapis.com",
    "aicode.googleapis.com",
    "generativelanguage.googleapis.com",
    "oauth2.googleapis.com",
    "accounts.google.com",
    "www.googleapis.com"
  ],
  "binary_path": "auto",
  "healthcheck": {
    "interval_minutes": 2,
    "connect_timeout_seconds": 2.5,
    "probe_port": 443,
    "retries": 3,
    "retry_delay_seconds": 1.0
  }
}
```

- **`smart_dns.servers`**: Список хостов или IP-адресов DNS-серверов. Все серверы опрашиваются параллельно, собираются все возвращённые IP-адреса, и каждый проверяется на работоспособность TLS SNI-проксирования. Также поддерживается одиночный `"host"` / `"fallback_ip"`.
- **`nodes`**: Список статических IP-адресов прокси-узлов (используются напрямую или объединяются с адресами от DNS).
- **`domains`**: Список доменов, которые направляются на прокси-узлы (рабочие эндпоинты, OAuth2 и авторизация Google).
- **`binary_path`**: `"auto"` для автопоиска в `~/.local/bin/agy`, `PATH` или `/opt/...`, либо прямой путь к файлу.
- **`healthcheck`**: Таймауты, число повторных проверок (`retries`) и интервал запуска таймера (`interval_minutes`).

## 🛠️ Справка по командам

| Команда | Описание |
|---|---|
| `sudo ag on` | Включить обход: пропатчить клиент, найти лучший IP и прописать в `/etc/hosts` |
| `sudo ag off` | Отключить обход: удалить записи из `/etc/hosts` и сбросить DNS-кэш |
| `ag status` | Показать статус бинарника, текущий узел и его задержку |
| `ag nodes` | Протестировать все доступные узлы и вывести таблицу задержек |
| `sudo ag check` | Проверить доступность узла с повторами и автоматически переключить при падении (`-q` для фонового таймера) |
| `sudo ag unpatch` | Восстановить оригинальный бинарник `agy` из бэкапа `.bak` |

## 🔍 Как это работает изнутри

1. **Сетевой движок — DNS и TLS SNI (`core/network.py`):**  
   Параллельно опрашивает настроенные DNS-серверы через собственный легковесный RFC 1035 UDP-клиент без сторонних библиотек. Затем проверяет каждого кандидата через прямой TLS SNI-хэндшейк (`daily-cloudcode-pa.googleapis.com:443`) и ранжирует узлы по минимальному пингу. При сбое автоматически переключает на живой узел.
2. **Системные модификаторы (`core/system.py`):**  
   - **Атомарный менеджер `/etc/hosts`:** изолирует записи между тегами `# BEGIN AG_BYPASS` и `# END AG_BYPASS`, сохраняет резервную копию `.ag_bak`, производит безопасную замену и сбрасывает DNS-кэш (`resolvectl flush-caches`).
   - **Эндпоинт `CLOUD_CODE_URL`:** настраивает переменные окружения для клиентских сессий.
   - **Бинарный патчер:** безопасно заменяет сигнатуру отказа региона `ineligible` на `inexigible` (10 байт в 10 байт) с созданием бэкапа `.bak`.
3. **Конфигурация (`core/config.py`):**  
   Обеспечивает гибкий поиск конфигурации (аргумент командной строки, переменная окружения, системные и пользовательские каталоги) и валидацию настроек.
